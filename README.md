# 🚀 server-init — VPN в один клик (3x-ui · двойной VLESS+Reality)

Один скрипт разворачивает на чистом сервере полностью настроенный VPN: панель **3x-ui** с **двумя надёжными каналами VLESS+Reality** и первым клиентом. После запуска вы заходите в панель из консоли — там уже всё работает, добавляете остальных клиентов в пару кликов.

Собрано и проверено на боевом сервере (Ubuntu 24.04, hostkey NL).

## Что разворачивается

- **Панель 3x-ui** (фикс. версия `v3.2.8` → Xray-core `26.6.1`) на случайном порту, случайном пути, со случайным логином/паролем и HTTPS.
- **Канал A — VLESS + XHTTP + Reality** (TCP/443): основной stealth-канал, маскируется под `www.microsoft.com`, `fingerprint=chrome`.
- **Канал B — VLESS + Reality + TCP + Vision** (TCP/8443): резерв на другом транспорте и порту. «Классический» Reality — **максимально совместим** (роутеры, старые клиенты) и стабилен после рестартов. Один клиент работает по обоим каналам — если по основному где-то затык, переключаетесь на резерв.
- **Сетевой тюнинг**: BBR + `fq`, увеличенные буферы — «чтобы летало».
- **Фаервол nftables**: deny-by-default, SSH-safe, блок исходящего SMTP (анти-абуз).
- **Самопроверка**: реально прогоняет трафик через ОБА канала и подтверждает работу.
- **На выходе в консоли**: ссылка на панель, логин/пароль, готовые ссылки и QR обоих каналов.

> **Почему не Hysteria2?** Встроенный в Xray hy2-inbound оказался нестабильным (баг ядра #5921 — перестаёт отвечать после рестарта Xray). Два VLESS+Reality канала на разных транспортах/портах дают надёжное резервирование без этого бага и покрывают те же сценарии.

## Установка (одной командой)

На **чистом** Ubuntu 24.04 / Debian 12 (root, amd64):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/denis-ne-normis/server-init/main/install.sh)
```

Через 2–3 минуты в консоли появятся доступы к панели и QR-коды каналов. Готово.

## Настройка (необязательно)

Параметры задаются переменными окружения перед запуском.

```bash
# пример: задать донора и фикс. порт панели
SNI_DONOR=www.twitch.tv PANEL_PORT=39000 \
bash <(curl -fsSL https://raw.githubusercontent.com/denis-ne-normis/server-init/main/install.sh)
```

| Переменная | По умолчанию | Описание |
|---|---|---|
| `SNI_DONOR` | `www.microsoft.com` | Донор Reality (TLS1.3+H2). Альтернативы: `github.com`, `www.twitch.tv` |
| `VLESS_PORT` | `443` | Порт канала A (VLESS+XHTTP+Reality) |
| `VISION_PORT` | `8443` | Порт канала B (VLESS+Reality+Vision) |
| `PANEL_PORT` | случайный | Порт веб-панели |
| `ENABLE_BACKUP` | `1` | `0` — не поднимать резервный канал B |
| `BLOCK_SMTP` | `1` | `0` — не блокировать исходящий SMTP |
| `FIRST_CLIENT` | `client-1` | Имя первого клиента |
| `XUI_VERSION` | `v3.2.8` | Версия панели (пусто = последняя) |
| `FORCE_REINSTALL` | `0` | `1` — переустановить панель поверх существующей |

## Клиенты

Рекомендуемые приложения: **Hiddify**, **NekoBox**, **v2rayN/v2rayNG**, **sing-box**.
Импорт: скопировать ссылку из консоли → «Добавить из буфера» / отсканировать QR.

- **Канал A (XHTTP)** требует свежее ядро Xray (≥ 26.x) — для телефонов/ПК с актуальным Hiddify это норма.
- **Канал B (Vision)** совместим почти со всем, включая роутеры и старые клиенты — используйте его там, где канал A не подключается.
- Добавьте обе ссылки в клиент и включите авто-выбор по доступности — переключение между каналами будет автоматическим.

## Где всё лежит после установки

- `/root/vpn-handoff.md` — памятка: доступы, ссылки, требования к клиенту.
- `/root/vpn-setup/secrets.env` — все секреты (chmod 600).
- `/root/vpn-setup/channelA_qr.png`, `channelB_qr.png` — QR-коды каналов.
- `/var/log/vpn-install.log` — лог установки.

## Повторный запуск

Скрипт **идемпотентен**: переиспользует уже сгенерированные секреты (`/root/vpn-setup/secrets.env`) и не создаёт дубликаты каналов. Безопасно гонять снова для донастройки.

## Требования к серверу

- Чистый VPS: **Ubuntu 24.04 (или 22.04) / Debian 12**, **amd64 (x86_64)**, root.
- Выход в интернет (apt + загрузка 3x-ui).
- Домен **не требуется** (сертификат — Let's Encrypt для IP либо self-signed).
- Если у хостинга есть **внешний фаервол** (security groups) — откройте там же: TCP **22**, **443**, **8443** и порт панели (задайте `PANEL_PORT`, чтобы знать его заранее).

## Безопасность

- Панель — только по HTTPS, на нестандартном порту/пути, со стойкими случайными кредами.
- Секреты генерируются криптостойко (`openssl rand`); приватный ключ Reality в клиент не уходит.
- Фаервол закрывает всё лишнее; правило SSH (22) стоит первым, есть авто-откат при ошибке.
- Рекомендуется после установки включить 2FA в панели.
