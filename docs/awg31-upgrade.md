# Переход существующего server-init на AmneziaWG 3.1

Проверенные источники на 25.09.2026: AmneziaVPN 5.0.3.0, AWG 3.1.
Версия пакета `amneziawg` вида `1.0.20210914-...` не равна версии протокола.
Обновление не устанавливает другие версии пакетов: оно проверяет возможности
уже загруженного модуля и tools реальным `setconf` в отдельном network namespace.

## Существующий сервер

До применения обновите приложение AmneziaVPN (проверен формат конфигов 5.0.3.0;
официальный минимум поддержки 3.1 — 5.0.1.5). Сохраните snapshot VPS. Выполняйте
обновление из SSH через обычный интернет или VLESS, не через изменяемый AWG.
Из полного checkout проверенного коммита:

```bash
sudo python3 awg_upgrade.py check
sudo python3 awg_upgrade.py apply
```

`check` только проверяет. `apply` делает приватную резервную копию, сохраняет ключи
сервера/клиентов, PSK, IP, порт, UUID/subId и персональные ссылки. Меняет именно
профиль маскировки, MTU и соответствующие экспорты. Создаёт новый общий секрет
HeaderProtectionKey, но не заменяет ключи идентичности WireGuard/Reality.
Перезапускается **только AWG**. VLESS/3x-ui, SSH, сертификаты и firewall не меняются.
После успеха обновляется установленный vpnctl, включая проверку NAT в doctor.

**Старые импорты AWG 2.0 после перехода НЕ подключатся.** Откройте прежнюю личную
страницу, заново скопируйте `vpn://` в AmneziaVPN и импортируйте как новый профиль.
Либо скачайте новый `.conf` для приложения AmneziaWG с поддержкой 3.1. Не меняйте
просто строку версии в старом файле. Один клиентский ключ нельзя одновременно
использовать на нескольких устройствах; каждому устройству нужен свой профиль.

```bash
sudo vpnctl doctor
```

Зелёный doctor подтверждает локальные проверки, не работу из конкретной мобильной
сети. Нельзя гарантировать обход блокировки UDP/адреса у провайдера.

## Отказ и откат

Если состояние неполное, ключи/экспорты расходятся, NAT отсутствует или версия
модуля/tools не понимает параметры, операция отказывается продолжать до изменений.
Отсутствие нашей таблицы NAT нельзя исправлять слепой перезаписью стороннего firewall.

При обычной ошибке во время применения выполняется восстановление старых файлов
и перезапуск AWG с прежним профилем. Отдельный аварийный журнал сохраняется на диске;
SIGKILL/отключение питания не являются атомарной транзакцией всей ОС.

Для явного возврата, из того же checkout:

```bash
sudo python3 awg_upgrade.py rollback
```

После успешного обновления также доступен `sudo vpnctl awg-rollback`.
Rollback восстанавливает только файлы своего изменения, а не всю базу 3x-ui/ОС.
Он отказывается затирать конфиги, изменённые вручную после миграции. После отката
работают прежние импорты AWG 2.0. Повторный apply после успеха — проверка/no-op;
общий секрет при этом не меняется. После отката новый apply создаёт новый профиль.

Архивы, журнал миграции, state.json, secrets.env и конфиги содержат секреты.
Не публикуйте их в GitHub и не пересылайте в поддержку целиком.

## Новый сервер

Новые установки по умолчанию создают AWG 3.1. `AWG_PROTOCOL=2` оставлен для
явного тестирования совместимости. Старые state без AWG_PROTOCOL всегда считаются
версией 2; repair не повышает версию неявно.

Профиль основан на исходниках AmneziaVPN 5.0.3.0: S1–S4=12, H1–H4=1–4,
HeaderProtectionKey, padding 10–100, интервалы rekey/keepalive и RandomTrailers.
MTU=1280 выбран по мобильному значению upstream. Cookie-защита от DoS сохранена
(`DisableCookies=off`), в отличие от upstream preset с отключёнными ответами-cookie.
Это осознанный компромисс, а не обещание максимальной устойчивости к DPI.
IPv4-интернет обслуживается NAT; IPv6 по-прежнему не раздаётся через сервер,
а `::/0` в клиенте предотвращает обход IPv4-only туннеля через IPv6.
